# 評価器の妥当性検証 2026-09-23 — 所見

数値は [summary.md](summary.md)（`npm run validate:agreement -- reports/validation/2026-09-23` で再生成できる）。
正解データは `data/human-evals/ogiri-ai/` の 07-10・07-11・09-15・09-23 セッション。

## 条件

- Jev 版: `humor-eval`・`fun-check` の `scripts/evaluate.ts` をそのまま実行（2回）。ベースラインとして、ルーブリックなしで「どれくらい面白いか」だけを聞く Jev の質問も用意した
- プロンプト版: Sonnet のサブエージェントが各 `SKILL.md` に従って判定した。`humor-eval` は2パス、その他は1パス。入力は `blind/` のとおりで、お題ごとに全セットの回答を混ぜてシャッフルし、出所は伏せた。`diversity-check` はセット単位で判定した
- ベースライン: ルーブリックなしの「面白い順に並べて」（プロンプト版）と、文字数の短さ

## 所見

1. **面白さの判定は、どの評価器もチャンスレベル。** 当たりの判別 AUC は 0.37〜0.61 で、95%区間はすべて 0.5 をまたぐ。ルーブリックを作り込んだ `humor-eval` も、ルーブリックなしのベースラインや文字数を上回っていない。
2. **セット単位の判定は、改悪の側を選ぶ。** プロンプト版 `humor-eval` の Overall は、人間のセット判定7件のうち一致が 0.29 だった。09-15 の節分（調整後を平均 3.20 vs 2.40、Overall 4 の本数 2 vs 0 で上にした）と、07-11 の FIRST TAKE（スキルありのアトラクター化したセットを 3.00 vs 2.50 で上にした）で、人間が退けた側を高く採点した。ogiri-ai の gate check が `humor-eval` の中央値で判定していれば、この2件の改悪は「検証済みの改善」として通っていた。
3. **Jev 版は安定しているが、妥当ではない。** 2回の実行間の相関は r≈0.99 だが、妥当性はプロンプト版と同程度。プロンプト版 `humor-eval` はパス間で r≈0.55 と揺れる。
4. **`fun-check` の「ベタ」「相対ベタ」は、人間の当たりの方に多く付く**（AUC 0.38〜0.41、つまり逆向き）。「一発で絵が見える大胆な回答が勝つ」（07-11）という人間の傾向を、減点として扱っている。
5. **`diversity-check` は人間が指摘した収束を拾えていない**（AUC 0.49）。拾えたのは 07-10 GPT の前前前世（同じ方向の回答が並ぶ、分解軸の収束）だけ。「痕跡＋小さい数字」型や「概念だけ」型のような文体・形式の収束は、軸の数が最大の5と判定した。
6. **役に立った点:** プロンプト版 `humor-eval` のレポート本文（`prompt-reports/`）は、セット内のほぼ同じ回答（レコ大の領収書のペア、ラジオ体操 第一/第二 など）を正しく指摘していた。数値ではなく、重複を検出する機械的な用途では使える。

## 注意

- サンプルは小さい（当たり22 / 回答75、セット比較7、回答ペア13）。評価者は1人。
- 回答ペア13件のうち8件（09-23 セッションで `purpose: evaluator-disagreement` のもの）は、プロンプト版 `humor-eval` が過去ラベルと食い違ったペアを選んだもの。そのため、プロンプト版 `humor-eval` の `pairs` 列は構造上低く出る。他の評価器にとっては、このような選抜の偏りはない。
- 09-23 のブラインド再評価では、人間は過去の自分の判定と同点を除く11件中10件で一致した。ラベルの信頼性は評価器よりはるかに高い。
- プロンプト版の判定モデルは Sonnet のみ。他のモデルは未検証。
