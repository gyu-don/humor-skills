## 3. 回帰判定（`gate.ts`）と人間の判定

対象は、ogiri-ai 2026-11-08 のゲートの5題（ブラインドは2題）。人間の判定は、変更後の版を選んだのが1題（シルバニア）、引き分けが4題。変更前の版を選んだ題はない。

| 規則 | 変更後が良い（1題） | 引き分け（4題） |
|---|---|---|
| 悪化があれば回帰（`> 0`、いずれかの指標） | 0〜1題 | **4題** |
| ノイズ幅を超えたら回帰（`> noise`、いずれかの指標） | 0題 | **3題** |
| うち `concrete` / `indirect` / `compare` | 0 / 0 / 0 | 1 / 1 / 1 |

ノイズ幅ありの判定は、2回の実行で全題同じだった。ノイズ幅なしでは、シルバニアの `concrete`（悪化幅 −.003 と +.003）が実行によって変わった。

- ノイズ幅を置くと、引き分けの題を回帰とする判定は、指標別には `concrete` と `compare` で 3題 → 1題に減った。それでも「いずれかの指標」では4題中3題を回帰とした（Codex の `concrete`、一言の `indirect`、五七五の `compare`）
- 依頼の表の事例はそのまま再現した。Codex は `concrete` が .059 悪化（ノイズ幅 .028〜.036）で回帰、人間は引き分け。一言は `indirect` が .047〜.054 悪化（ノイズ幅 .012）で回帰、人間は引き分け。どちらも `compare` はノイズ幅の中に入った（Codex .494、一言 .452、ノイズ幅 .06〜.07）。シルバニアはどの規則でも回帰なしで、人間の判定（変更後が良い）と矛盾しない
- 五七五の `compare` は、変更前の1回目と2回目がほぼ互角だったので、ノイズ幅が .002〜.004 しかなかった。1組の実行から測るノイズ幅は、たまたま小さく出ることがある
- 人間が変更前の版を選んだ題がないので、**悪化を検出できるかは確かめられていない**。わかったのは、人間が差を感じなかった題で回帰とする誤りが、ノイズ幅を置くと減るが残る、ということだけ
- `trait-check` が測るのは具体性と説明的さで、面白さではない。引き分けの題で回帰と判定されても、その性質が実際に悪化した可能性はある。ゲートで人間の判定の代わりに使うには、変更前が勝った事例で検出できることの確認が要る

ノイズ幅の規則は `SKILL.md` に「暫定、検出は未検証」と書いて入れた。誤りが減る方向で、検出の悪化は測れていない（悪化の事例が0件）。
