# 被りチェック

同じお題への回答群を受け取り、「同じセットに並んでいたら、どちらか片方で足りる」ペアを返す。
自動テスト（生成スキルの改善ループの合否）に使える。

## 必要なもの

- Node.js 22.6以上
- 環境変数 `TYPESAFE_API_KEY`
- 初回のみ、このスキルのディレクトリで `npm install`（依存は `@typesafe-ai/sdk` 1つだけ）

## 使い方

1. お題と回答を `{"topic": "...", "answers": ["...", ...]}` 形式のJSONに書き出す。複数セットは `[{"id", "label", "topic", "answers"}, ...]`（見本は `assets/samples.json`）
2. `node scripts/evaluate.ts <入力ファイル> [出力ファイル]` を実行する
3. 出力JSONを読む
   - `summaries[].nearDuplicates`: 被りと判定したペア（回答番号の組）。Jev の確率0.7以上か、句読点・空白を除いた完全一致
   - `overlaps[]`: 全ペアの `sameMaterial`（同じ素材を使っている確率）

## 判定の基準

- 被り: 笑いの中心の素材（物・人・場所・出来事）が同じ
- 被りではない: お題の前提そのものの共有、書き出しなど表面の言葉だけの共通、お題が決める形式の共通

ペアを1組ずつ独立に聞くので、「被りを探せ」という圧力がかからない。セット全体を見せて被りを探させると、類似のないペアにも被りを見いだす。

## 信頼度

人間のブラインド判定16組で較正した（humor-skills の `reports/validation/2026-09-23-overlap/notes.md`）。

- 被り5組中3〜4組を検出（1組が閾値0.7付近で、実行ごとに揺れる）
- 被りでない10組の誤検出は0
- 同じ入力の2回の実行間の相関 r≈0.99

`nearDuplicates` が1件以上あれば不合格、という絶対条件に使える。
ただし、お題が回答の形式を決める場合（全回答がカタカナ語、など）はペアの確率が閾値のすぐ下に来る。件数の増減は、変更前の版のセットと並べて読む。

## 検出できないもの

素材は違うが同じ方向の読み替え（例: 古代に現代の書き込みを持ち込む回答が並ぶ）によるセット全体の収束は、ペア単位の質問では被りでないペアと区別できなかった。この種の収束は人間が確認する。
