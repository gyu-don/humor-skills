# 被りチェック

## 準備

- Node.js 22.6以上、環境変数 `TYPESAFE_API_KEY`
- 初回のみ、このディレクトリで `npm install`

## 使い方

```
node scripts/evaluate.ts <入力.json> [出力.json]
```

- 入力: `{"topic": "...", "answers": ["...", ...]}`、または複数セットの配列（見本は `assets/samples.json`）
  - 配列の各要素の `id`・`label` は任意。`id` がなければ `set-1`、`set-2`… と位置で振る。結果は `id` で引くので、`id` が重複していればエラーで止まる
- 出力:
  - `summaries[].nearDuplicates`: 被りと判定したペア（回答番号の組）
  - `overlaps[].sameMaterial`: 全ペアについて、同じ素材を使っている確率（0.7以上を被りとする）

被りとみなすのは、笑いの中心の素材（物・人・場所・出来事）が同じペア。お題の前提、書き出しの言葉、お題が決める形式が共通しているだけなら被りではない。

## 合否の決め方

`nearDuplicates` が1件以上あれば不合格。

お題が回答の形式を決める場合（全回答がカタカナ語、など）は、確率が閾値のすぐ下に集まる。そのときは、変更前の版と `sameMaterial` を並べて比べる。

## 複数回の生成をまとめて渡すとき

複数回の生成をまとめて1セットとして渡すと、`nearDuplicates` には、別々の実行で同じ素材が出た組も入る。これは1回の出力の中の被りではなく、生成モデルが同じ素材に寄る傾向を示す。ogiri-ai の 2026-11-08 の実験では、2回分10本の被りのほとんどがこちらで、変更前の版にも同じ傾向があった。

- 1回の出力の中の被り（合否の対象）を見るときは、実行ごとに別のセットとして配列で渡す
- 実行をまたいだ繰り返しを見るときはまとめて渡し、被りの組がそれぞれどの実行の回答かを照らし合わせる。変更前の版をまとめたセットと件数を比べる

## 検出できないもの

素材は違うが同じ方向にひねった回答が並ぶ、セット全体の収束。これは人間が確認する。

## 信頼度

人間のブラインド判定16組（2026-09-23）での結果は次のとおり。2回の実行間の相関は r≈0.99。

- 被り5組のうち3〜4組を検出した
- 被りでない10組の誤検出は0

2026-11-09 に測り直すと、誤検出は 0/10 のまま、検出は 3/5（閾値ちょうどの1組が外れた）。被りの判定を1組足した16組では、検出 3/6。

2026-11-15 も誤検出は 0/10 のまま、検出は 4/6。閾値を決めた後に足した判定は被りの1組だけで、これは検出できなかった。被りでない組の新しい判定はまだなく、誤検出 0 は閾値を決めたのと同じ16組での値。最新の値は humor-skills の `STATUS.md` にある。
