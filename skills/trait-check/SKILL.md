# 性質チェック

## 準備

- Node.js 22.6以上、環境変数 `TYPESAFE_API_KEY`
- 初回のみ、このディレクトリで `npm install`

## 回答ごとの採点

```
node scripts/evaluate.ts <入力.json> [出力.json]
```

- 入力: `{"topic": "...", "answers": ["...", ...]}`、または複数セットの配列（見本は `assets/samples.json`）
- 出力: `summaries[].means` にセット平均、`rows[].traits` に回答ごとの値
  - `concrete`: 具体的な物・現象・異常が出てくる確率。高いほど良い
  - `indirect`: 説明的・遠回しに言っている確率。低いほど良い

## 一対比較

```
node scripts/compare.ts <入力.json> [出力.json]
```

- 入力: `{"topic": "...", "answerA": "...", "answerB": "..."}`、または配列（見本は `assets/pairs.json`）
- 出力: `results[].probA`（A の方が良い確率）、`winner`（`A` / `B` / `draw`）、`criteria`（`concrete` と `straight` それぞれで A が勝つ確率）

## 合否の決め方

同じお題で、変更前の版と変更後の版の回答を比べる。次のどれかなら差し戻す。

- 変更後の `concrete` のセット平均が下がった
- 変更後の `indirect` のセット平均が上がった
- 変更前後の回答を総当たりで一対比較して、変更後の勝率が0.5未満

悪化の検出にだけ使う。値が上がったことを採用の理由にしない。この値を最大化させると、回答が同じ型に収束する。
1本の回答の合否にも使わない。

## 信頼度

人間の判定との一致（2026-09-24）は次のとおり。質問を作ったのと同じデータで測った値なので、楽観的に読む。

- `concrete`: AUC 0.67
- `indirect`: AUC 0.62〜0.64
- 一対比較: 66%

2回の実行間の相関は r≥0.97。
