# 性質チェック

大喜利の回答が次の2つの性質を持つかを、確率で返す。

- **具体性**（`concrete`、高いほど良い）: 質感のある具体的な物、実際に起きている現象、制度・設備・役割の具体的な異常が出てくるか。ルールや概念の言い換えだけの回答は低い
- **説明的**（`indirect`、低いほど良い）: 同じ着眼点を、説明的・遠回しに言っているか。直球で短く言い切った回答は低い

生成スキルの改善ループで「前の版より悪化していないか」を確かめる自動テストに使う。

## 必要なもの

- Node.js 22.6以上
- 環境変数 `TYPESAFE_API_KEY`
- 初回のみ、このスキルのディレクトリで `npm install`（依存は `@typesafe-ai/sdk` 1つだけ）

## 使い方

### 回答ごと（`scripts/evaluate.ts`）

1. お題と回答を `{"topic": "...", "answers": ["...", ...]}` 形式のJSONに書き出す。複数セットは `[{"id", "label", "topic", "answers"}, ...]`（見本は `assets/samples.json`）
2. `node scripts/evaluate.ts <入力ファイル> [出力ファイル]` を実行する
3. `summaries[].means`（セット平均）と `rows[].traits`（回答ごと）を読む

### 一対比較（`scripts/compare.ts`）

1. `{"topic": "...", "answerA": "...", "answerB": "..."}` 形式のJSONに書き出す。複数は配列（見本は `assets/pairs.json`）
2. `node scripts/compare.ts <入力ファイル> [出力ファイル]` を実行する
3. `results[].probA`（Aの方が良い確率）、`winner`（A / B / draw）、`criteria`（`concrete` と `straight`、それぞれでAが勝つ確率）を読む

各質問はA/Bの提示順を入れ替えて2回聞き、平均して位置バイアスを打ち消す。

## 自動テストでの使い方

同じお題で、変更前の版と変更後の版の回答を並べて比べる。

- 回答ごと: 変更後の `concrete` のセット平均が下がった、または `indirect` が上がったら差し戻す
- 一対比較: 変更前と変更後の回答を総当たりで比べ、変更後の勝率が0.5を下回ったら差し戻す

**上がったから採用、には使わない。** どちらの性質も、人間が褒めた回答から抜き出したものである。
生成側がこの数値の最大化に向かうと、全回答が同じ型に収束する（ogiri-ai の 2026-07-11 に、「痕跡＋小さい数字」の助言でこれが起きた）。
下限の確認に限り、被りチェック（`overlap-check`）と人間の抜き取り確認を組み合わせる。

## 信頼度

人間の判定での検証（humor-skills の `reports/validation/2026-09-24/notes.md`）:

| 指標 | 人間との一致 |
|---|---|
| `concrete`（回答ごと） | 当たりの判別 AUC 0.66〜0.67、セットの優劣 7件中6件 |
| `indirect`（回答ごと） | AUC 0.62〜0.64 |
| 一対比較 `probA` | 同じセット内の当たり×外れ50組の66%、人間が直接比べた13組中10組 |

- 同じ入力の2回の実行間の相関は r≥0.97
- 1本の回答の合否に使えるほど強くはない
- 質問は、同じ検証データから書かれた人間の所見をもとに作った。新しいお題で人間の判定を取るまでは、上の数値は楽観的な値と読む
